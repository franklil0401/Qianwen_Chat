## 明确保留的差异

- 语音通话、拍照/图片理解、视频生成有官方展示，但属于本期范围外。[截图 3][shot3]、[截图 5][shot5]
- 定时任务、品牌服务、支付下单、文件成果编辑不在本期范围内；不放置可点击但无效的入口。[产品页][store]、[开放平台][open]
- 本项目会话只保存在当前浏览器；不宣称跨设备云同步。本次资料不足以核实千问完整的历史同步行为。
- 本地演示知识库必须明确标注来源，不能将它包装为千问联网搜索；计算工具和资料检索是本项目的功能选择。
- 停止按钮、新消息打断、取消传播及旧流隔离来自面试需求和 `AGENT.md`；官方静态截图不能验证这些机制。
- 不复制千问商标或宣称官方客户端；借鉴信息结构与交互原则，应用保持自己的名称和视觉实现。

## 三轮自查与改进建议

下列是待执行的检查清单，并非已经发现的缺陷。每轮需要实际操作、修复与证据，记录到 `docs/iterations.md`，通过检查后分别提交和推送。

### 第一轮：输入、阅读与 PC 布局

- 对照聊天截图，检查空态是否能直接开始、输入框是否明确、双方消息是否易辨认、生成反馈是否及时。
- 检查 1440 × 900 和 1024 像素宽度：侧栏、内容宽度、长标题、Markdown 表格/代码块、输入区不遮挡最后一条消息。
- 检查 Enter、Shift + Enter、中文输入法组合输入；所有显示的按钮都应有实际行为和可识别名称。
- 检查阅读历史时不被强制拉回底部，返回最新内容的入口可见且有效。
- 留证：两种桌面尺寸截图，以及真实流式问答、长文阅读、换行输入的操作结果。

### 第二轮：工具过程、成果与后续操作

- 对照成果与任务卡片，检查参数接收、执行、成功、失败、取消能否区分；完成卡片应优先展示有用结果。
- 验证计算器由模型真实调用、结果可复制；检索结果有标题、来源和摘要，原文可展开。
- 验证选中资料追问确实将该资料带入后续上下文；无匹配时如实说明并允许修改问题。
- 检查失败卡片和不完整参数不会永久加载；通用错误应能看懂，技术参数放在展开详情内。
- 留证：两个真实工具闭环、结果操作及一次可控失败；不能仅以截图或假数据认定联调通过。

### 第三轮：打断、恢复与最终体验

- 验证流式中停止、停止后立即发送、新消息直接打断、工具阶段停止；旧事件不能回写新回复。
- 验证生成中切换/删除会话、刷新恢复；中断记录如实呈现，后续提问不会携带缺少结果的工具调用。
- 验证断网/服务错误后的提示与继续操作，长历史和本地存储异常不会阻塞输入。
- 完成键盘焦点、错误状态可见性、复制反馈及完整演示流程检查；复查前两轮修复未引入回归。
- 留证：关键自动化检查结果、最终截图、真实 API 演示步骤和剩余限制；完成后交用户体验验收，暂不启动桌面打包。

## 2026-09-29 追加范围的实施依据

本次根据用户明确要求增加语音、图片、文件、联网及账号同步。接口采用阿里云官方模型文档核对，并通过实际 Key 调用验证；没有新增手机 App 实机测试。

- [视觉理解](https://help.aliyun.com/zh/model-studio/vision)：服务端将上传的实际图片交给视觉模型。
- [录音文件识别](https://help.aliyun.com/zh/model-studio/non-realtime-speech-recognition-user-guide)与[语音合成](https://help.aliyun.com/zh/model-studio/realtime-tts-user-guide)：实现录音后转写、分段合成播放与取消；未实现双向实时通话。
- [联网搜索](https://help.aliyun.com/zh/model-studio/web-search/)：采用原生 DashScope 接口取得检索来源，再呈现来源列表。图片与联网同时开启时，先取得网页证据，再由视觉模型结合图片回答。
- 文档通过本地 PDF / DOCX / UTF-8 文本解析进入模型上下文，不等同于千问完整的文件工作台或在线编辑能力。
- 按用户选择，账号同步先提供本地服务、按账号隔离和手动版本同步。未部署云端，也未验证手机千问的内部同步实现。

继续保留的差异：手机拍照流程、实时语音通话、扫描文件 OCR、视频生成、品牌服务、定时任务及成熟账号管理。当前交付仍为 PC 布局网页。
