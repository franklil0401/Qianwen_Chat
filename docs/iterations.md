## 第一轮 v0.2.0：输入、阅读与 PC 布局（已完成，提交 8729c37）

实际检查发现：输入与正文偏小，辅助文案对比度不足；历史对话缺少搜索；代码块没有单独复制入口；PC 快捷键尚未实现；完成状态不够明确。

改进：输入与正文提升到 16px，调整辅助文字对比度；增加标题及消息内容搜索、代码语言栏和独立复制；增加 Ctrl/⌘+K 新建、Ctrl+/ 聚焦、Esc 停止；回答完成状态明确呈现。参考官方截图中的正文层级、结构化内容和底部集中输入，搜索与快捷键属于本项目的 PC 适配判断。

验证：42 项核心测试、9 项浏览器测试、类型检查和构建通过。新增浏览器覆盖历史搜索、快捷新建、代码独立复制、中文组合输入、Shift+Enter、1024 宽度下长表格和代码滚动，以及返回最新消息。

证据：[1440 首页](screenshots/round1-home.png)、[1024 代码与表格](screenshots/round1-chat-1024.png)。后一截图使用受控 Markdown 回复检查排版，不替代真实模型联调。

## 第二轮 v0.3.0：工具成果与资料追问（已完成，提交 c518f69）

实际检查发现：检索摘要和来源藏在展开区域，缺少一眼可读的结果；点击追问会把整篇原文塞进输入框，用户不便编辑自己的问题；计算结果的小数位截断可能将很小的数显示为 0。

改进：工具成果直接显示摘要与来源，原文按需展开；选择资料形成可移除引用，保留用户草稿，已发送引用随历史保存；当前与后续模型请求均携带资料 ID、来源和原文。空结果提供实际的换关键词动作，计算显示与复制保持一致。引用合并后超长会在发送前提示并保留草稿。

验证：42 项核心测试、12 项浏览器测试、类型检查与构建通过。新增测试验证引用进入当前及后续上下文、移除引用、刷新恢复、计算复制、工具空结果及失败后的继续交互。另在真实浏览器中执行千问资料检索并选择引用，草稿保持不变。

证据：[真实千问检索与引用截图](screenshots/round2-live-knowledge.png)。

## 第三轮 v0.4.0：长会话、恢复与异常体验（已完成）

实际检查发现：12 轮较长中文对话可产生 303,396 字节的请求，在后端裁剪前触发 256KB 限制；本地历史的嵌套工具结果和资料引用缺少完整校验，损坏数据可能导致页面报错；超过 50 个会话时可能丢弃当前会话。

改进：发送前按 UTF-8 字节预算保留完整近期回合，最新问题和引用不被截断，原先 413 的用例现返回 200；严格校验历史工具结果、引用和错误字段，保留可用内容并提示恢复情况；统一保存与恢复容量规则，优先保留当前会话。补充弹窗焦点约束与恢复、本地服务重连、准确的配置状态提示，以及旧 Markdown 回复的渲染缓存。

验证：56 项核心/后端测试、19 项浏览器测试、类型检查和生产构建通过。覆盖损坏存储不白屏、未完成工具恢复、停止后立即再发送、跨会话新请求、生成中删除会话、长中文请求、弹窗 Tab/Esc、存储写入失败和服务重连。独立只读复审确认先前发现的三个缺口均已修复。

交付方式：新增 Windows 后台启动/停止命令，已实际验证停止和重启，构建地址为 `http://127.0.0.1:3001`。

最终真实验证：构建服务上的四项 `test:live` 全通过（13 个普通回复增量、计算结果 394.6666666666667、检索命中 2 条、生成中取消）。另外在真实 Chrome 页面开启深度思考并调用计算工具，得到 8192；随后生成长文、中途点击停止、立即发送新问题并正常回复，页面无未捕获异常。这些线上检查按顺序运行，因为应用限制同时一个活动生成任务。

证据：[最终首页](screenshots/final-home.png)、[真实深度思考与计算工具](screenshots/final-live-chat.png)。依赖审计为 0 项已知漏洞。API Key 未包含在提交文件或前端产物中。

## 第四轮 v0.5.0：编辑与重新生成

用户追加五轮迭代。本轮检查发现正常回答缺少重新生成入口，用户无法修改历史问题后保留原记录比较结果。

改进：用户消息可编辑后重发，回复可重新生成；从所选问题创建独立分支，保留此前上下文及资料引用，排除该问题的旧回答和后续消息。来源信息刷新后保留，可返回原对话。编辑时明确提示分支行为，取消编辑恢复草稿；生成期间禁用这些操作，避免重复请求。

验证：61 项核心测试、21 项浏览器测试、类型检查与生产构建通过。新增测试确认任意历史回合的上下文边界、旧对话保留、刷新后的来源、取消编辑不发请求，以及修改问题后正确提交。浏览器回复使用受控 SSE，截图为测试数据：[编辑提问](screenshots/round4-edit.png)。

## 第五轮 v0.6.0：按会话保存草稿

实际复现：输入文字并选择资料后，切换会话或刷新会丢失待发送内容；无消息的会话还可能被“新对话”复用覆盖。

改进：文字与资料引用直接存入所属会话，侧栏显示草稿标记，搜索可查草稿。空会话存在草稿时不会被复用；切换和刷新恢复对应内容。编辑历史问题使用独立临时输入，取消、刷新、切换和创建分支均保留原会话草稿；正常发送清空对应草稿，预检失败则保留。

验证：62 项核心测试、23 项浏览器测试、类型检查及构建通过。新测试覆盖双会话草稿隔离、引用刷新后进入模型上下文、发送后清空、带草稿空会话的新建保护，以及编辑/重新生成不移动原草稿。测试中修正了“空白新会话应出现在历史列表”的错误假设，并独立断言实际存储保留全部三个会话。

证据：[草稿和引用恢复](screenshots/round5-drafts.png)，使用受控测试数据。

## 第六轮 v0.7.0：阅读偏好与对比度

实际测量发现工具摘要、成功状态和思考正文的文字对比度约 2.70–3.20:1，且固定 12px 阅读吃力。

改进：侧栏新增阅读设置，支持浅色、深色、实时跟随系统，以及标准/大号内容字号。文字、工具结果、引用、代码、异常状态和分支提示同步配色；偏好独立持久化，存储失败时当前页面仍生效。设置中可查看现有快捷键，Esc 关闭设置并返回焦点，不会同时停止生成。

验证：66 项核心测试、25 项浏览器测试、类型检查与构建通过。浏览器逐项检查主题实时变化、手动偏好优先及刷新恢复、大号字号；两种主题下工具摘要、成功状态、思考正文、错误信息和代码文字的实际计算对比度均不低于 4.5:1，1024px 无页面横向溢出。

证据：[浅色阅读](screenshots/round6-light.png)、[深色阅读](screenshots/round6-dark.png)，使用受控测试内容。截图仅在显式设置 `UPDATE_SCREENSHOTS=1` 时更新，常规回归不覆盖历史版本证据。

## 第七轮 v0.8.0：本地备份与恢复

实际检查发现历史只保存在当前浏览器来源，缺少转移与备份入口；直接导出持久化快照还会遗漏运行期超出保存条数的消息。

改进：显式导出当前内存的全部消息、工具结果、引用、分支信息和草稿。导入严格校验版本及嵌套内容，先预览新增数量与容量裁剪，再追加确认；标识冲突时统一重建导入会话 ID 并关联分支。未完成回复恢复为中断，不重放工具。导入会重新检查当前会话与 6M 字符恢复容量，先成功写入浏览器存储再更新界面，写入失败保留原数据。

容量规则：10 MB 文件、合计 50 个会话、每个导入会话最近完整回合最多 100 条消息。原有运行期记录不因导入被裁剪；导出文件不裁剪。另修复独立复审发现的矮窗口阅读浮层裁切，按触发器位置动态限制高度，备份浮层也可滚动。

验证：73 项核心测试、29 项浏览器测试、类型检查与构建通过。覆盖全量导出、严格拒绝损坏文件、ID 冲突及分支重映射、预览后状态变化、容量上限、停止状态归一化、导入确认/取消、刷新恢复和存储失败回滚。全部备份操作不调用模型。1024×520 阅读设置与备份操作可达。

证据：[备份导入预览](screenshots/round7-backup.png)，使用受控测试数据。当前生产入口 JS 为 511KB（gzip 153KB），构建成功但触发 Vite 的 500KB 体积提示；下一轮评估模块拆分。

## 仍保留的产品差异

本轮对照的是官方公开资料和截图，未在手机上安装登录千问。语音、图像、文件上传、联网搜索、定时任务和账号云同步不在当前实现范围。PC 会话导航、键盘快捷键和本地存储是本项目的适配选择。网页仍需用户体验验收，通过后才进入桌面应用阶段。
