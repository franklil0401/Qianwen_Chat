## 第三轮 v0.4.0：长会话、恢复与异常体验（已完成）

实际检查发现：12 轮较长中文对话可产生 303,396 字节的请求，在后端裁剪前触发 256KB 限制；本地历史的嵌套工具结果和资料引用缺少完整校验，损坏数据可能导致页面报错；超过 50 个会话时可能丢弃当前会话。

改进：发送前按 UTF-8 字节预算保留完整近期回合，最新问题和引用不被截断，原先 413 的用例现返回 200；严格校验历史工具结果、引用和错误字段，保留可用内容并提示恢复情况；统一保存与恢复容量规则，优先保留当前会话。补充弹窗焦点约束与恢复、本地服务重连、准确的配置状态提示，以及旧 Markdown 回复的渲染缓存。

验证：56 项核心/后端测试、19 项浏览器测试、类型检查和生产构建通过。覆盖损坏存储不白屏、未完成工具恢复、停止后立即再发送、跨会话新请求、生成中删除会话、长中文请求、弹窗 Tab/Esc、存储写入失败和服务重连。独立只读复审确认先前发现的三个缺口均已修复。

交付方式：新增 Windows 后台启动/停止命令，已实际验证停止和重启，构建地址为 `http://127.0.0.1:3001`。

最终真实验证：构建服务上的四项 `test:live` 全通过（13 个普通回复增量、计算结果 394.6666666666667、检索命中 2 条、生成中取消）。另外在真实 Chrome 页面开启深度思考并调用计算工具，得到 8192；随后生成长文、中途点击停止、立即发送新问题并正常回复，页面无未捕获异常。这些线上检查按顺序运行，因为应用限制同时一个活动生成任务。

## 第七轮 v0.8.0：本地备份与恢复（提交 75789df）

实际检查发现历史只保存在当前浏览器来源，缺少转移与备份入口；直接导出持久化快照还会遗漏运行期超出保存条数的消息。

改进：显式导出当前内存的全部消息、工具结果、引用、分支信息和草稿。导入严格校验版本及嵌套内容，先预览新增数量与容量裁剪，再追加确认；标识冲突时统一重建导入会话 ID 并关联分支。未完成回复恢复为中断，不重放工具。导入会重新检查当前会话与 6M 字符恢复容量，先成功写入浏览器存储再更新界面，写入失败保留原数据。

容量规则：10 MB 文件、合计 50 个会话、每个导入会话最近完整回合最多 100 条消息。原有运行期记录不因导入被裁剪；导出文件不裁剪。另修复独立复审发现的矮窗口阅读浮层裁切，按触发器位置动态限制高度，备份浮层也可滚动。

验证：73 项核心测试、29 项浏览器测试、类型检查与构建通过。覆盖全量导出、严格拒绝损坏文件、ID 冲突及分支重映射、预览后状态变化、容量上限、停止状态归一化、导入确认/取消、刷新恢复和存储失败回滚。全部备份操作不调用模型。1024×520 阅读设置与备份操作可达。

证据：[备份导入预览](screenshots/round7-backup.png)，使用受控测试数据。当前生产入口 JS 为 511KB（gzip 153KB），构建成功但触发 Vite 的 500KB 体积提示；下一轮评估模块拆分。

## 第八轮 v0.9.0：流式边界与最终生产验收

独立检查实际复现三项问题：累计 8,412 字符的工具参数报错后仍留在历史，导致下一问返回 400；未知结束原因或空工具调用被误当成正常完成；大于 2,000,000 字符的完整 SSE 事件绕过发送后的大小检查。

改进：工具增量先校验候选值再更新卡片，错误终态保留最后合法参数；严格校验结束原因和工具调用内容，不执行未正常完成的调用；逐行累加 SSE 事件长度，在发送前阻止超限，并允许一个大网络块包含多个合法事件。新增 14 项协议回归测试，包含通过真实本地 Express 接口提交错误卡片后继续提问，确认返回正常 SSE。

最后复审还发现备份中的用户问题与引用合并后可能超过 API 的 16,000 字符限制。现在聊天与备份复用同一个引用序列化函数，导入前按实际请求内容校验；助手长回复仍按其自身上限处理。新增回归覆盖超长问题、长引用和合法长助手回复。

构建改进：应用入口约 58KB；React、Markdown、图标和校验库分块，最大约 223KB，消除 500KB 单块提示。目的是让依赖独立缓存，不代表总下载量减少。生产浏览器确认全部资源加载、分块依赖无环、Markdown/代码/表格/工具卡片正常。

验证：88 项核心测试、29 项浏览器测试、TypeScript 与生产构建通过。全部浏览器用例另在 3001 的生产构建上执行；扩展对比度检查后发现浅色工具开关为 4.35:1，修正状态选择器后重新验证，两种主题的正文、工具、错误、代码及主要操作文字均达到 4.5:1。主题截图关闭动画，避免把 150ms 的切换中间态误当成最终颜色。

真实验证：`test:live` 四项通过（12 个普通回复增量、计算结果 394.6666666666667、检索命中 2 条、中途取消成功）。真实 Chrome 页面开启深度思考并调用计算器得到 8192，重新生成到新分支后再次正确回答；原会话草稿保留，刷新恢复主题与草稿；生成长文中途停止后立即继续提问成功，页面无未捕获异常。线上检查顺序执行，避免单活动任务限制导致相互取消。

最终交付：构建服务后台运行于 `http://127.0.0.1:3001`。依赖审计为 0 项已知漏洞；源码、待提交文件及前端产物未检出实际 API Key。五个追加版本分别提交并 push。

## 桌面交付 v0.13.0：Windows 安装包与安装后验证

两轮改进完成后，按用户授权制作 Electron 桌面应用和普通用户 NSIS 安装程序。应用内置运行时和本地服务，不要求用户安装 Node.js；主进程读取系统模型配置，页面不接触 Key。中文菜单提供重载、缩放、编辑、配置说明和打开数据目录；网页来源交给系统浏览器，上传图片使用受控的独立预览窗口。

数据保存在 `%APPDATA%/QianwenChat`，浏览器持久化和账号/附件服务分别存放。固定本机端口 18439 配合每次启动随机访问令牌，普通浏览器不能调用桌面接口；所有窗口开启沙箱和上下文隔离，只有主页面可申请音频录制，摄像头和预览窗口录音被拒绝。正常退出先保存浏览器数据和 Cookie，再取消活动任务并关闭数据库、解析进程及 HTTP 端口。

打包时保留后端独立 bundle，文档解析器及依赖解包到真实路径，并使用 Electron 的 Node 模式运行解析子进程；子进程不继承模型凭据。图标由项目原有紫色标记绘制为矢量后生成多尺寸 ICO。构建输出先清理固定生成目录，避免旧资源混入；产物检查排除用户数据、开发目录及实际模型 Key。
